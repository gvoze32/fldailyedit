# FL Daily Edit

[![Версия Python](https://img.shields.io/badge/python-3.10%2B-blue.svg)](https://www.python.org/)
[![Лицензия: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](../../LICENSE)

FL Daily Edit обновляет составы команд в SP Football Life 2026 и eFootball PES 2021, применяя реальные трансферы к файлу сохранения `EDIT00000000`.

> **Создание проверенных новых игроков включено по умолчанию в `players apply`,
> если доступен корректный донор `PlayerAppearance.bin`. Положительный параметр —
> `--allow-create`; используйте `--no-allow-create`, чтобы отключить создание
> через CLI. Прямые вызовы API по-прежнему отключены по умолчанию.**
>
> Трансферы для игроков, которые уже есть в сохранении, и проверенные обновления для
> существующих игроков продолжают поддерживаться. Отсутствующие игроки пропускаются.
> Ролевое освобождение overflow включено по умолчанию; используйте
> `--no-allow-overflow-release`, чтобы оставить заполненный состав без изменений.

> [!WARNING]
> **Уведомление о бета-версии:** FL Daily Edit, данные репозитория и созданные сборки всё ещё проходят тестирование. Они могут работать не с каждой конфигурацией игры/сохранения; некоторые условия пока не поддерживаются.

## Совместимость

Предоставленная база предназначена для **SP Football Life 2026**. Требования:

- Football Life 26 Update 2.2
- SmokePatch's National Squads Update

Она несовместима с UML, более ранними версиями FL26 или установками без обновления национальных сборных. После установки файла сохранения необходимо начать новую карьеру в Master League или Become a Legend.

[Включенная база](../../base/EDIT00000000) — это файл
[Gondowan's EDIT от 22 августа 2026 года](https://www.reddit.com/r/SPFootballLife/comments/1vvh129/release_gondowans_edit_file_22082026_latest/).
Она содержит последние трансферы на 22.08.2026 для всех лиг, изменения рейтингов
более чем у 600 игроков, повышения и понижения между первым и вторым дивизионами,
исправления роста, позиций, имен и номеров, изменения доступных тренеров и
автоматические составы, отсортированные по лучшим игрокам. Она не создает новых
игроков и не добавляет клубы, вышедшие из третьих дивизионов.

## Установщик Windows

Установщик Windows — рекомендуемый вариант для начинающих. Интерфейс установщика пока доступен только на английском языке. Текущие проверенные загрузки предназначены **исключительно для Football Life 2026 Update 2.2 + SmokePatch's National Squads Update**. Обнаружение vanilla eFootball PES 2021 поддерживается, но установка остаётся отключённой до публикации подходящей проверенной базы.

1. Скачайте и распакуйте [FLDailyEditInstaller.zip](https://github.com/gvoze32/fldailyedit/releases/download/latest/FLDailyEditInstaller.zip).
2. Закройте игру.
3. Выберите **Fast** или **Deep**. Это раздельные варианты охвата обновлений, для каждого из которых отображается время генерации.
4. Подтвердите обнаруженную папку Football Life 2026 или используйте **Browse** при необходимости.
5. Нажмите **Download and install**. Установщик проверит загрузку, создаст резервную копию текущего сохранения и атомарно заменит его.

**Обновление существующего сохранения через GUI:** Установщик также может
обновить выбранный пользователем файл `EDIT00000000` со стандартной структурой
вместо установки готовой сборки. Выберите **Update my local save**, укажите
обнаруженное расположение или используйте **Browse**, выберите **Fast** или
**Deep** и после проверки нажмите **Apply update**. Мастер проверяет файл
сохранения перед внесением изменений, создает резервную копию на месте и
отображает ход выполнения, результат или диагностические данные. Локальная
применимость не зависит от метки SPFL/PES/UML, и этот путь не загружает
удаленную готовую сборку. Если эти необязательные внешние каталоги SPFL
недоступны, локальный модуль сопоставления использует имена игроков и команд,
встроенные в выбранное сохранение, благодаря чему локальное обновление может
работать и без них.

> [!WARNING]
> Исполняемый файл установщика не подписан, поэтому при запуске Windows SmartScreen может показать предупреждение. Перед продолжением сравните загруженный `FLDailyEditInstaller.zip` с контрольной суммой `FLDailyEditInstaller.zip.sha256`, опубликованной в [последнем релизе](https://github.com/gvoze32/fldailyedit/releases/tag/latest).
> Если Windows блокирует установщик через Smart App Control, откройте **Settings → Privacy & security → Windows Security → App & browser control → Smart App Control settings** и переключите в положение **Off**. Либо щелкните правой кнопкой мыши по загруженному файлу, откройте **Properties** и установите флажок **Unblock**, если он доступен.

Для ручной установки без установщика загрузите общедоступный [ZIP-архив версии Fast](https://github.com/gvoze32/fldailyedit/releases/download/latest/fldailyedit-fl2026-fast.zip) или [ZIP-архив версии Deep](https://github.com/gvoze32/fldailyedit/releases/download/latest/fldailyedit-fl2026-deep.zip). Распакуйте `EDIT00000000`, сделайте резервную копию текущего сохранения и скопируйте извлеченный файл в папку:

`Documents\KONAMI\eFootball PES 2021 SEASON UPDATE\2026\save\`

Для запуска по запросу или использования собственного списка клубов создайте форк репозитория и используйте **Run workflow** на вкладке Actions.

## Что обновляется

- Трансферы, расторжения контрактов, аренды и возвращения из аренды
- Доступные номера на футболках на основе данных о составах от FotMob
- Идентификаторы игроков, проверенные по текущему составу FL26
- Расстановки и тактические схемы, затронутые изменениями в составах
- Отчеты о трансферах и журналы аудита в формате JSON Lines
- Ежедневные готовые файлы сохранения через GitHub Actions
- Проверенные создания игроков и исправления атрибутов с помощью явных команд Player Update

Программа обновления не перезаписывает номер на футболке, который уже используется другим игроком команды. Она также проверяет текущий клуб игрока перед применением трансфера.

Все текущие задачи плана развития завершены. Ждём следующую полезную идею.

## Безопасность и ограничения

- Локальные запуски создают ротируемые резервные копии и используют атомарное проверенное шифрование.
- Файлы сохранения проверяются до и после изменений в составах.
- Блокировка процессов предотвращает одновременную запись двух экземпляров в один и тот же файл.
- Неполные снапшоты FotMob приводят к остановке работы во избежание создания поврежденного сохранения.
- Неоднозначные совпадения игроков и несовпадения клубов-источников пропускаются.
- Заполненные составы принимающих клубов используют ролевое освобождение overflow
  по умолчанию. Основные игроки и заявочная скамейка защищаются, предпочтение
  получает самый глубокий native reserve, а созданные игроки защищаются при наличии
  native-кандидата. Ability/OVR не используется; отключить это можно через
  `--no-allow-overflow-release`.
- Wikipedia, Sortitoutsi и Transfermarkt являются дополнительными источниками. Сбой в одном из них не аннулирует полный снапшот FotMob.

**Обновления трансферов и Player Updates**

Это раздельные рабочие процессы:

- `run` обрабатывает трансферы игроков, которые уже есть в файле сохранения. Если принимающий
  клуб заполнен, самый безопасный ролевой overflow-кандидат освобождается по умолчанию;
  используйте `--no-allow-overflow-release`, чтобы пропустить трансфер.
- `players apply` применяет проверенные изменения характеристик. Спецификации `update` для
  существующих игроков поддерживаются.
- Спецификации `create` для новых игроков по-прежнему можно загружать и проверять.
  `players apply` пытается применить их по умолчанию при наличии явного донора и корректного
  источника `PlayerAppearance.bin`. Используйте `--no-allow-create`; отсутствие или ошибка
  донора оставляет файл без изменений.
- Для `players apply` заполненный состав также использует ролевой overflow по умолчанию.
  Положительный параметр — `--allow-overflow-release`; `--no-allow-overflow-release` отключает его.

## Локальный запуск

Локальная настройка поддерживается в macOS, Linux и Windows через WSL. Требуется Python 3.10 или более поздней версии.

```bash
git clone https://github.com/gvoze32/fldailyedit.git
cd fldailyedit

python3 -m venv .venv
source .venv/bin/activate
pip install -e .

cd vendor/pesXdecrypter
make
cd ../..
```

## Основные команды

```bash
# Preview changes without writing a save
python run.py run --dry-run --edit-file base/EDIT00000000

# Validate an existing save
python run.py validate --edit-file base/EDIT00000000

# Validate one-file-per-player updates against the pristine base revision
python run.py players validate

# Apply reviewed Player Updates explicitly to an existing output save
python run.py players apply \
  --base-revision fl26-u2.2-national-squads \
  --edit-file output/EDIT00000000 \
  --in-place

# Apply all effective transfers available through today
python run.py run --window auto

# Rebuild from the bundled base
python run.py run --from-base --window auto

# Update a specific save in place
python run.py run --edit-file /path/to/EDIT00000000 --in-place

# Show every run option
python run.py run --help
```

| Команда | Назначение |
|---|---|
| `run` | Применяет только проверенные трансферы |
| `players validate` | Проверяет все Player Update относительно исходной базы |
| `players apply` | Явно применяет проверенные Player Update к файлу сохранения |
| `base-audit` | Проверяет активные Player Update, клубы назначения и parent loan по базе |
| `base-refresh` | Проверяет и при необходимости продвигает локальную или HTTPS-базу |
| `usage-import` | Объединяет CSV-данные использования игроков с release policy |
| `players apply --preflight` | Показывает проверенные цели create и параметры безопасности без записи |
| `log` | Показывает недавно примененные трансферы |
| `inspect` | Проверяет команды, количество игроков и смещения в файле сохранения |
| `validate` | Проверяет заявки в составы и сопоставления планов на игру |
| `repair` | Восстанавливает устаревшую базу с помощью эталонных сохранений |
| `audit` | Аудит файла сохранения и нативных метаданных только для чтения |
| `compare` | Сравнение двух вариантов нативных CPK только для чтения |

Команда `run` обрабатывает исключительно трансферы: она никогда не загружает и не применяет Player Update. Чтобы объединить оба рабочих процесса, сначала выполните команду трансферов для выходного файла сохранения, а затем выполните `players apply --in-place` для того же файла.

## Обновления игроков (Player Updates)

Каждое проверенное Player Update представляет собой отдельный завершенный JSON-файл схемы версии 2 на каждого игрока в каталоге `players/`. Он фиксирует операцию (`operation`: `create` или `update`), жизненный цикл (`active`, `upstreamed` или `retired`), точные базовые ревизии в `applies_to`, постоянную идентичность игрока и происхождение UUID/профиля Pes Retro Stats, подтверждающие ссылки и проверенные данные PES. Обновления типа create содержат предлагаемую полную запись игрока и данные состава целевого клуба. Обновления для существующих игроков содержат только поддерживаемые значения, отличающиеся от проверенной базы; каждое изменение фиксирует точные значения `from` и `to`.
Записи `create` по-прежнему поддерживаются схемой для проверки. Изменение через CLI
требует `players apply --allow-create` и корректных данных внешности; прямые вызовы API
по умолчанию отключены. Если состав заполнен, добавьте `--allow-overflow-release`;
отсутствующие или ошибочные данные безопасности оставляют файл без изменений.
Поддерживаемые группы обновлений: способности, владение позициями, стиль игры, навыки игрока, стили COM, национальность, физические/базовые параметры и зарегистрированная позиция.
- Сгенерированные контрольные значения OVR являются детерминированными расчетами на основе опубликованной формулы PES 2021. Они служат вспомогательным средством для паритета, а не независимой гарантией поведения игры во время выполнения; предложенные значения способностей по-прежнему требуют проверки.
- Черновики игроков, сгенерированные с предыдущим идентификатором модели OVR, необходимо сгенерировать заново перед валидацией; неявная миграция с v1 на v2 отсутствует.

### Простой способ через Issue

1. Откройте [форму создания issue для обновления игрока](../../.github/ISSUE_TEMPLATE/player-update.yml).
2. Настроенный рабочий процесс генератора загружает этот профиль и открывает черновой PR, содержащий предложение `players/<player-slug>.json` схемы версии 2. Он извлекает из профиля моментальный снимок источника, идентичность, физические параметры, данные о позициях, способности, стиль игры, навыки и стили COM.
3. Для создания нового игрока только внутриигровые параметры, недоступные в источнике, остаются перечисленными в `draft.missing`: PES ID и отображаемые имена для профиля и игрока, ID и название команды, ID национальности, цвет кожи и цвет радужки. Участник сообщества или мейнтейнер должен их указать. Для обновления генератор находит игрока в проверенной базе и выводит только фактические различия `from`/`to`. Позиция из источника, не поддерживаемая в PES 2021 (например, `RWB`), опускается, а не переназначается, в том числе при изменении зарегистрированной позиции.
4. Участник сообщества и мейнтейнер проверяют каждое сгенерированное значение как неутвержденное предложение. CI принимает Player Update только в том случае, если PR добавляет или изменяет ровно один канонический JSON-путь игрока, и общий семантический валидатор завершает работу успешно.
5. Слияние (merge) PR означает окончательное утверждение человеком. Отдельный флаг `approved` в JSON-файле отсутствует.

Ожидается, что каждое сгенерированное предложение не пройдет валидацию полного файла. Чтобы преобразовать сгенерированные подтверждения в полную схему v2, удалите поля, предназначенные только для черновика: `evidence.current_team`, `evidence.issue_number` и `evidence.issue_url`; сохраните канонический `evidence.profile_url`, проверенные `evidence.proof_urls` и точную `evidence.effective_date`; добавьте проверенное непустое значение `evidence.reason`. Сохраните канонический UUID профиля как `identity.pes_retro_stats_id` и оставьте в объекте `pes` только проверенные параметры геймплея. При создании нового игрока также заполните все внутриигровые поля, указанные в `draft.missing`. PES ID создаваемых игроков должны быть уникальными и составлять не менее `0x100000` (1 048 576); модуль распределения предложений остается в этом зарезервированном диапазоне.
Затем перед полной валидацией удалите объекты верхнего уровня `source` и `draft`, которые представляют собой метаданные чернового варианта, предназначенные исключительно для проверки.

### Прямой способ через PR с одним файлом

Опытный участник сообщества может пропустить генерацию черновика через issue и напрямую открыть PR, который добавляет или изменяет ровно один готовый файл `players/<player-slug>.json`. Укажите каноническое происхождение UUID/профиля в `identity` и `evidence`, подтверждающие ссылки, проверенные значения PES, ожидаемые базовые значения для обновления, жизненный цикл и точную базовую ревизию, после чего выполните команду `python run.py players validate` перед запросом на проверку. Не включайте метаданные верхнего уровня `source` или `draft` сгенерированного черновика. Не включайте в этот PR другие изменения кода или документации.

Применение всегда выполняется явной командой и требует точной ревизии из `data/base_manifest.json`; несовпадение ревизий приведет к ошибке до начала расшифровки целевого файла сохранения.

### Жизненный цикл ревизий

При изменении официальной базы обновите `base/EDIT00000000` и `data/base_manifest.json` одновременно. Сохраняйте историю Player Update в `players/`; не удаляйте их только из-за изменения ревизии. Активное Player Update, список `applies_to` которого не содержит новую ревизию, становится неактивным: валидация сообщает о `needs_review`, а применение пропускает его. После проверки добавьте новую ревизию только в том случае, если Player Update по-прежнему актуально, пометьте его как `upstreamed`, если официальная база уже включает эти изменения, или как `retired`, если оно больше не применимо.

Основные параметры `run`:

| Параметр | Назначение |
|---|---|
| `--deep` | Получить данные по всем клубам FotMob, проиндексированным локально |
| `--club "Chelsea,Arsenal"` | Ограничить запуск выбранными клубами |
| `--window auto` | Воспроизвести все доступные датированные трансферы по сегодняшний день |
| `--window summer` | Использовать последний период с 1 июня по 30 сентября |
| `--window winter` | Использовать период с января по февраль выбранного года |
| `--since YYYY-MM-DD` | Вручную установить нижнюю границу даты |
| `--dry-run` | Спланировать изменения без записи в файл сохранения |
| `--from-base` | Начать с `base/EDIT00000000` |
| `--fotmob-only` | Запустить без дополнительных источников трансферов |
| `--release-policy PATH` | Загружает защищённых игроков по клубам и offline-счётчики использования |
| `--numbers-only` | Исправить текущие номера только по данным составов FotMob |

Без параметра `--from-base` обычный запуск продолжается с последнего проверенного результата. Это предотвращает исчезновение трансферов при повторном чтении накопленной истории последующим запланированным запуском.

## Источники трансферов

FotMob предоставляет основную историю трансферов и метаданные составов. Сезонные списки Wikipedia, одобренные заявки на трансферы SortitoutSI и проверенные датированные записи Transfermarkt дополняют или подтверждают трансферные переходы. Профили Pes Retro Stats предоставляют сформированные на основе источников, но еще не утвержденные предложения для черновиков Player Update.

Записи из различных источников согласовываются без потери дат, идентификаторов, ссылок и подтверждений. События без даты, вступающие в силу в будущем, противоречивые или неоднозначные события не могут обновлять сохранение самостоятельно.

Сопоставление игроков начинается с состава исходного клуба и использует состав принимающего клуба в качестве идемпотентного запасного варианта. Позиция, национальность и возраст учитываются только при наличии соответствующей информации.

```bash
pytest -v
```

Набор тестов охватывает парсинг и валидацию сохранений, согласование трансферов, планирование составов, историю аренд, сопоставление игроков, ограничения по размеру составов, отчеты, резервное копирование и блокировку процессов.
